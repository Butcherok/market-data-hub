# Market Data Hub

[DATA-COLLECTION UTILITY] — это не торговый бот и не боевой код, чек-лист production-бота (раздел 5 project instructions основного проекта) к этому репозиторию не применяется.

Веб-приложение для сбора и просмотра исторических данных Binance (spot + USDⓈ-M futures) для бэктестов. FastAPI-бэкенд + React/Vite/TypeScript фронтенд.

## Что делает

- Собирает 1-минутные OHLCV-бары с Binance (spot и USDⓈ-M futures) в локальный SQLite, с полной историей с момента листинга инструмента.
- Ресемплит на лету в 5m/15m/30m/1h/4h/1d для просмотра и экспорта CSV — с биржи всегда качаются только минутки, это единственный источник правды.
- Список торгуемых символов, tickSize/stepSize/MIN_NOTIONAL — всегда программно из /exchangeInfo, не захардкожены.
- Явно логирует дыры в данных (gaps), не заполняет их синтетически.
- Live-прогресс сбора через SSE, можно отменить на лету.
- Полный файл SQLite скачивается одним кликом — для бэктеста напрямую.

## Запуск

### Backend

```
cd backend
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env   # при необходимости — токен авторизации, путь к БД
uvicorn main:app --host 0.0.0.0 --port 8000
```

### Frontend

```
cd frontend
npm install
npm run dev   # http://localhost:5173, слушает на 0.0.0.0
```

## Почему это нельзя запустить в облаке

Binance блокирует запросы с датацентровых/облачных IP (HTTP 451 "restricted location") — это ограничение биржи, не хостинга. Поэтому сбор данных и бэкенд должны работать на обычном "домашнем" IP: твой ПК, VPS с жилым/резидентским IP и т.п. Подробности и результаты проверки — в trading_bot_project_brief.txt основного проекта.

## Доступ с разных устройств (Tailscale)

1. Установи Tailscale на ПК, где крутится бэкенд+фронтенд, и на устройство, с которого заходишь — в один и тот же tailnet (один аккаунт).
2. Узнай Tailscale-IP ПК: `tailscale ip -4` (вида 100.x.x.x).
3. С другого устройства открой `http://100.x.x.x:5173` — фронтенд автоматически обратится к бэкенду на том же хосте, порт 8000 (см. frontend/src/api.ts).

### Альтернатива — ngrok

`ngrok http 5173` (и отдельно `ngrok http 8000`, либо прокинуть один туннель и проксировать оба порта). Важно: ngrok-адрес публичный — обязательно задай `MARKET_DATA_AUTH_TOKEN` в .env бэкенда, иначе к твоей базе сможет обратиться кто угодно, у кого есть ссылка.

## Данные и приватность

- SQLite-файл (backend/data/market_data.db) и .env не коммитятся (см. .gitignore).
- API-ключ Binance не требуется — все эндпоинты сбора публичные (klines, exchangeInfo).
- Проскальзывание/комиссии/funding нигде не моделируются — это чистый сборщик рыночных данных, не симулятор исполнения.

## Статус

Рабочие параметры (таймфрейм 1m, обе площадки для USDCUSDT и т.д.) — экспериментальные, см. раздел 3 project instructions основного проекта. Финальный инструмент/алгоритм для боевой торговли требует отдельного исследования.
